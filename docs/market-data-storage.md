# 公共市场数据持久化与准确性

本轮仅本地开发，不自动发布或推送。用户明确取消成交量长期存储：K线库只存日期及OHLC价格，不以成交量差异阻止价格入库；现有即时行情、分时接口的成交量字段不改动。

## 数据范围

- 日、周、月K线：证券/市场、周期、复权方式、来源分别隔离，按需积累近10年。内存→持久化→现有来源。PostgreSQL按每根K线保存，元数据和价格事务切换，不按用户或页面请求重复保存。
- 原始财报金额、股本变动、原始公告日期、分红方案、已实施分红：保存来源输入，PE/PB/股息率重新计算，不把历史计算结果当原始事实。财报额外保留计算所需前置年度。
- 条件选股财报按公司共享，不为每个分组复制公共财报。五分钟刷新来源输入；历史估值输入及港股当前财务/分红三十分钟刷新。不同公司真实报告期不强行对齐。
- 不存账户登录信息、持仓、交易指令、全量实时刷新、分钟历史或筛选结果。
- 每条来源输入标记 structural，表示通过结构/逻辑检查，不表示逐份原始公告核验。

## 存储部署

`MARKET_DATABASE_URL`（优先）或既有 `DATABASE_URL`：服务器PostgreSQL；需要建表权限。使用独立的 `fin_market_records`、`fin_market_bars`、`fin_market_revisions`、`fin_market_incidents`，不改个人表。连接/查询有超时，连接池4；故障继续源站读取。

开发环境默认写入被Git忽略的 `data/market`。生产不默认使用临时文件，除非明确设置 `MARKET_DATA_DIR` 持久卷。文件适配器仅适用于单进程本地开发，不能当多实例数据库。WorkBuddy浏览器Cloud Auth/个人云同步不能直接替代此服务器数据库；本轮未取得或连接生产数据库。

`MARKET_DATA_STORE=off` 关闭持久化，保留上游校验和原有数据源。不清库。

## 更新及故障原则

1. 原始价格只补旧区间和近期重叠窗口；较早历史价格冲突进入事件记录，不静默覆盖。周/月未结束期间继续更新。
2. 复权序列按来源整体刷新，覆盖不足时不拼接旧版本；新版切换保存旧版。来源切换不混合不同供应商价格。
3. 不把当前日期之外、证券/周期/复权身份错配、无效价格、重复日期写入价格库；不修补成看似合法的OHLC，不伪造缺失价格。
4. 部分分页失败有 `complete:false`。所有响应保留实际日期和样本数量；不把短序列等同于全区间完整，上市前/停牌区间不负缓存为永不重试。
5. 上游失败时，已存K线可作为明确标记 stale 的结果；过期财务/公告/股本输入不悄悄与当前价格拼出新估值，更新失败则相关计算缺失或明确返回旧的完整估值。
6. 数据库不可用时，源站有效值仍可返回；K线写入未成功会附带提示。存储校验失败不会覆盖损坏文件。
7. 每个键保留最近4个被替换版本；PostgreSQL异常事件30天清理，本地异常每键保留最近20条。当前有效输入不是到期立即删除。旧季度组合或长期未访问输入的全局过期清理尚未自动启用，防止误删研究依据。

## 股息

- 同一实施记录精确重复只算一次，同一身份金额矛盾不直接求和。
- 已实施现金息与预期方案分开。A股静态滚动股息按除息日 `(去年同日, 当日]`，闰日夹到月末；送转后调整每股基础。
- 新浪显示精度低于东方财富已实施方案时，仅在该显示精度半单位内协调到较精细值，保留 `cashSource`，不是原文核验。
- 超出显示舍入的冲突保留两边原值和事件标记，相关TTM静态股息区间留空。旧冲突不让无关的新年度股息率全部失效；预期方案不混入已实施值。
- 港股保留已存在的“完整财年静态”标签，不因缓存改为TTM；港元折算金额不明仍留空，旧指标中的供应商隐含汇率不标成独立核验汇率。港股历史股息/复权/PIT能力未新增保证。

## 实测与仍待核验

2026-10-21运行 `node scripts/audit-market-sources.mjs`：十家公司，腾讯/新浪各近80个已结束交易日日线，OHLC未见差异；成交量历史差异符合整数手/小数手显示舍入（按用户要求不进入价格库）。2025年报归母利润与东方财富逐公司对照，差值0～48.5元，在新浪万元字段显示舍入范围内。分红部分有舍入差异，也发现长江电力2016年实施金额的来源冲突；后者不能按一致处理。

证据写在 `data/market-audit/latest.json`（不进Git）；每次运行有采样时间、来源、日期、原始数值及差异。它是聚合来源对照，不是交易所或发行人原文独立审计，更不是全市场十年每个原始值均准确的证明。

用户提供的PTrade结果目前只有统计摘要，没有原始CSV数值，因此PTrade逐日/逐字段数值对照仍待补充。不将 `returned` 或 `ok` 状态当作准确性证明，不替换网站主来源为PTrade。

验证包括：重启适配器复用、旧区间补抓、价格去重、当日更新、复权版本切换、历史冲突隔离、数据库故障、校验和损坏、并发CAS、财报范围隔离、分红去重及日历年边界。另使用隔离PGlite PostgreSQL 0.5.10引擎执行真实建表/JSONB/事务/逐根写入/批量财报/版本/CAS SQL，不连接生产。上线仍需实际PostgreSQL连接与权限验证、备份及多实例压力验证。
