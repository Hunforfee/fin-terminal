# 五年历史、数据库读取与 QMT 首次导入

本轮分工：本地编写国金普通 QMT 下载脚本，用户在自己的客户端运行；WorkBuddy 负责服务器导入和最终部署。网站改造负责接口补齐、共享数据库读取、收盘更新与校验。用户已完成实际 QMT 导出，544 只 A 股共 635,843 条日线已导入本地文件适配器，244 只港股仍待后台补齐。没有连接生产市场库。服务器统一导入命令与验收步骤见仓库根目录 `WORKBUDDY_QMT_IMPORT.md`。

## 普通 QMT 下载脚本

`scripts/qmt-probe.py` 检查内置 Python 与接口；`scripts/qmt-export-watchlist.py` 使用普通 QMT 的全局 `download_history_data` 及 `ContextInfo.get_market_data_ex(..., subscribe=False, fill_data=False)`，不依赖 MiniQMT，也没有交易调用。用户操作副本与私有自选 CSV 放在仓库外 `D:\ChatGpt\QMT_watchlist`，不提交清单和下载结果。清单803行，去重788只（A股544、港股244）。先跑环境检查，再默认3只样本；验证实际客户端结果后将 `SAMPLE_MODE` 改为 `False`。支持逐股SHA256断点校验、失败清单及ZIP导出。前复权和除权因子仅作来源参考，不直接接入现有估值计算。

本地完成 Python 3.5语法兼容、清单解析、价格校验、断点续下及ZIP模拟测试共4项。用户真实QMT导出后，本地对全部原价文件及参考文件完成 SHA256 和 ZIP 一致性检查，并抽样比较两只证券最近16个已完成交易日与网站来源的 OHLC，未发现差异；这不等于全部证券的交叉来源核验。红太阳的唯一长间隔已对照发行人停复牌公告，保留原始覆盖警告。网站生产构建通过，本地自选页已验证两类更新入口与无浏览器错误；完整回归后修正了模拟器的跨环境Error类型，再通过相关任务与存储复测。生产库导入及真实财务源完整性仍按下文验收。

## 网站行为

- 自选公司增加「补齐5年」，按当前已同步分组提交。已有原始数据复用，缺口从网站原有数据接口补齐；新增自选不要求再次操作 QMT。
- 「更新数据」刷新近期行情、财报、分红与股本；已初始化公司的近期更新还会重建估值输入，检查五年覆盖。新公司须先使用「补齐5年」。
- 所有用户共享证券级市场数据；个人分组仅用于权限与更新范围。同一证券的任务合并，全站一个后台证券任务，浏览器关闭不影响进度。
- 一次后台调用只执行一个阶段；有租约、续期、有限重试及限流暂停。五年任务不会将每个阶段完成冒充整家公司完成。
- 前台估值和财报默认5年；存储沿用最多10年滚动清理。五年历史估值另需起点之前的财报和股本状态用于 TTM，不能只存五份年报。
- 已完成的价格区间、缺口与核验时间写入 `market-coverage:v1:<symbol>:5`。`ready` 表示已执行结构、范围及估值可用性检查，不代表逐份公告人工审计或严格时点回测数据库。原始财报仍可能包含后续重述。

## WorkBuddy 的最小导入接口

先只导入 QMT **不复权日线**，其他估值与财报输入可由网站「补齐5年」处理，避免把 QMT 原始字段冒充新浪／东财字段。

网站仓库已经提供服务器函数 `src/lib/marketImportedBars.ts` 的 `importDailyPrices(store, input)`。WorkBuddy 在受信任的服务器导入程序中调用：

```ts
import { getMarketStore } from './src/lib/marketStore';
import { importDailyPrices } from './src/lib/marketImportedBars';
const store = getMarketStore();
if (!store) throw Error('市场数据库尚未配置');
await importDailyPrices(store, {
  symbol: 'sh600519',
  source: 'qmt',
  // 可选：仅填已核实的首次上市日期，不能用此次下载第一天代替。
  listingDate: '2001-08-27',
  candles: [
    // 实际应为近五年全部已完成交易日，升序，不是本例中的一条数据。
    { date: '2026-10-20', open: 1300, high: 1320, low: 1290, close: 1310 },
  ],
});
```

以上价格仅说明格式，禁止作为真实行情导入。此函数是服务器代码，不是开放的网页上传接口。凭证、用户身份、文件分批与导入权限由 WorkBuddy 的受信任导入任务管理；不向浏览器暴露数据库连接或执行器密钥。

要求：

1. 取日线、`dividend_type=none`、关闭缺失日填充（例如 `fill_data=False`）；保留真实证券代码、币种和交易日期。港股是否可用必须实测权限，不因 A 股下载成功推断港股完整。
2. 使用交易所当地日期 `YYYY-MM-DD`，OHLC 为每股价格，A 股人民币、港股港元；不填零、不以停牌填充线当实际成交。无需导入分钟、逐笔或成交量。
3. 导入函数检查日期升序、重复、未来日期、有限价格及 OHLC 关系。18:30（北京时间）前排除当天尚未最终收盘确认的日线；不对已有区间做缩短或静默改价。上市日期仅可来自已核实的证券基础信息。
4. 原始价格写入 `kline:v2:<symbol>:day:none:canonical:prices-only`，来源与覆盖分段存入 `origins`。通过 `MarketStore.write` 写入，**不要直接修改 `fin_market_records` 的 JSON 或自行计算 digest**：K线元数据、逐日表、版本与 CAS 必须一致。
5. 完成后用真实账号同步自选，在对应分组点「补齐5年」。网站会补足前复权价格、历史三表/指标、真实财报公告日期、股本、已实施分红及分红方案，并写覆盖检查记录。不要仅以 QMT 下载成功或日线数量认定历史 PE、PB、股息已经可用。
6. QMT 导入文件和运行数据保存在数据库／外部文件，不提交 Git。如果另外导入 QMT 财务数据，先做字段、币种、金额单位、累计/单季、报告日/披露日及普通股权益映射；本轮没有接受任意 QMT 财务 JSON 的公共导入端点，不能直接塞进现有来源缓存。

## QMT 与后续接口衔接

导入后的不复权日线只补近期尾部。首次及后续衔接要求至少3个重叠日（新上市不足3天则核对已有全部），同时比较 OHLC；不一致记录异常，保留原数据，不混接。新增分段标记真实网站接口来源，不把后续价格继续标成 QMT。历史已收盘价格发生修订时同样需要复核。

前复权价格会随除权调整整段历史；当前接口未提供已验证、可统一计算的全量因子链，所以采用完整窗口刷新，不能把昨日的旧前复权序列直接接上今日新前复权价格。这部分可能重新读取五年复权窗口；原始日线则继续增量。QMT 下载的前复权数据暂不直接与接口序列混合。

周/月线在数据库读取模式下由日线聚合，不重复下载与存储。实际覆盖不足、无已核实上市日期或估值起点缺失时，任务保留可用数据并报告缺口。范围边界允许14日非交易日缓冲；这不是逐日交易日历完整性证明，停牌和缺失日仍需结合发行人信息与交易日历抽验。港股没有可核验历史披露日和分红快照时，继续只提供已支持的当前估值，不伪造历史曲线与分位。

## 配置与切换顺序

继续沿用 `WORKBUDDY_MARKET_UPDATES.md` 的 PostgreSQL、登录签名和受监管 worker 配置：

```text
MARKET_DATABASE_URL=<服务器连接串>
MARKET_UPDATE_WORKER_ENABLED=1
MARKET_UPDATE_WORKER_TOKEN=<至少32字符私密随机值>
MARKET_UPDATE_ORIGIN=https://实际站点
MARKET_CLOSE_UPDATE_ENABLED=1
```

`MARKET_CLOSE_UPDATE_ENABLED=1` 后，worker 按北京时间18:30安排收盘任务，次日06:30开始补偿检查；采用周末回退，不冒充完整节假日日历。节假日实际没有新交易日时不生成假K线；页面展示真实末条日期。每天范围来自已登记账号自选的并集。用户访问自选页或提交任务时，服务器以已同步自选刷新登记；导入器也可调用 `registerCollection(store, owner, symbols)`，owner 必须与当前登录系统一致（`legacy:<userId>`），不得信任浏览器自报身份。删除全部自选可以登记空数组移除该账号的自动更新范围。

排队失败不会阻塞已有任务执行；批次进度持久化，后续继续，不把队列已满当作更新完成。收盘与次晨各有一轮，缺失日期由来源真实记录补齐，不仅下载固定“昨天一天”。服务停机后的下次启动能继续已保存任务并进行补偿。

先完成导入、少量样本与全自选覆盖验收，再设置并重启：

```text
MARKET_READ_MODE=database
```

该模式下，前台历史行情和财务只读数据库，过了抓取TTL的已存历史仍可读；未入库明确报缺，不由页面隐式下载。即时行情和证券搜索仍可联网，明确触发的 AI 联网研究、认证及短信流程不受市场数据开关影响。只有受预算限制的后台采集上下文可访问历史接口。缺少数据的全市场非自选公司也不会静默在线下载。

未完成实际自选初始化前不要全站开启数据库读取模式。本地预览使用隔离文件适配器，不是生产数据库验收。回退时取消 `MARKET_READ_MODE=database` 即恢复原有混合读取，不清空库；不要通过删库回退。

## 验收

- 先选一只普通 A 股、一只分红送转较多股票、一只新上市公司；港股另外核验币种和能力范围。将 QMT 原价与网站来源重叠日及发行人分红公告抽样对照。
- 五年日线起止、非交易日与停牌处理；TTM 使用累计金额，历史估值按真实披露日生效；静态与预期股息率保持原有口径区分。
- 新增自选后补齐、重复点击、页面关闭、服务重启、请求限流、数据库写入失败和来源冲突；失败项应可重试，不能返回假成功。
- 开启数据库模式后禁止历史网络请求，仍能查看已入库估值/财报；缺数据有明确提示。独立 worker 持续更新，在日志中核验收盘与次晨任务和十年清理。
- 部署平台须支持单阶段300秒请求，或将执行器迁移为常驻后台服务；网页发布不等于执行器和定时更新已经运行。
