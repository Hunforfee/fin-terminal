# 自选分组按需更新

WorkBuddy 部署入口见根目录 `WORKBUDDY_MARKET_UPDATES.md`，包括已建数据库的接入、独立执行器和生产验收要求。

## 使用方式

自选公司页的分组工具栏增加“更新数据”。更新当前分组的股票，忽略指数、基金；后台保存任务，页面关闭后无需继续保持轮询。重新进入页面可读取当前账号最近的任务。进度区分完成、近期已更新、等待、执行、失败，可重试当前分组失败项。

这是日常按需更新，不是强制清空缓存，不提供普通用户全市场或十年历史重抓入口。已有输入未过期就复用；确认写入有效记录才将公司记为完成。失败时可能已有部分有效记录入库，任务仍显示失败，不以“抓取成功”冒充整家公司完成。

完成后的前台刷新只读取当前可见页，翻页时按需读取新可见页，不重新启动所有自选公司的抓取。当前股息率所需的近期价格同样使用 `recentOnly`，避免刷新表格间接触发全历史复查。

## 范围与口径

- 近期不复权日线：请求最近 60 个自然日、最多 40 个交易日；已有更长历史继续保留。复用现有结构校验、源间抽样、冲突隔离和存储确认，不增加成交量存储。
- 后台显式启用 `recentOnly`，不会触发现有 K 线存储的每周全历史复查；该复查保留给普通历史查询。近期更新也不延长原全历史复查时间，避免短更新掩盖历史缺口。
- A 股：最新候选报告期财务输入、分红方案、已实施分红、股本变动。复用选股和估值已有输入键及有效期，避免另建一份计算结果缓存。
- 自选列表实际展示的四项财务指标使用 `watchlist-financial-inputs:v1:{symbol}`，列表接口与后台共用同一记录（30 分钟有效期），不再被另一个小时级页面缓存遮挡。保留原页面需要的近两年四项序列，不抓十年三表。
- 港股：近期日线、最新已规范币种的财务输入、派息事件，复用 PB/股息模块。
- 不借此生成十年估值图、不重抓十年三大报表、没有空记录时不伪造“零分红”。无法核验的无分红、缺记录等情况会保留失败结果，供后续复核。
- 近日派息冲突不算成功；历史无关冲突不阻断当前更新。数据校验通过不等于发行人公告原文已审核。

## 压力控制与恢复

同一时刻全站后台队列只处理一家公司。并发提交通过持久存储的 CAS 防重；跨实例租约确保不同执行器不会同时开工。同股活跃任务共享，已完成公司 10 分钟内跳过；每账号仅一个活跃任务，重复提交返回已有任务。一分钟提交冷却。

每家公司后台源请求串行，上一请求结束后至少间隔 1.5 秒；每次最多 40 个源请求、210 秒执行预算。HTTP 403/429 立即打开熔断，停止本任务的后续源请求，队列全局暂停至少 5 分钟。单镜像 501 WAF / 503 不代表其他镜像也被限流：本任务不再请求该主机，按既有顺序低速尝试下一镜像。失败最多三次自动执行，退避 1 分钟、3 分钟；不会无休止重试。

单次最多 1000 家股票，队列最多 2000 个共享公司任务与 50 个任务记录。已完成记录优先淘汰，最多保留 24 小时。此上限可在有运行数据后调整，不提供用户“加速”按钮。

5 分钟任务租约、每 20 秒续期；进程停止后任务仍在数据库，执行器恢复会重领过期任务。旧租约不能覆盖新执行结果。后台 HTTP 通过 AsyncLocalStorage 隔离，普通浏览请求不会继承后台的请求预算或熔断。普通页面现有抓取链路不属于后台队列的全站限速范围，仍依靠原有缓存与降级。

## 登录与权限

当前远端已恢复用户名密码登录：按钮使用同源签名 Cookie，服务端验证会话并从账号存储读取已同步分组及股票范围。有效 Cookie 优先于旧 Cloud token，前端不再读取或发送旧 Cloud 凭证。

服务端另保留 WorkBuddy Cloud Auth 兼容路径：实际访问 Cloud Auth `/v1/user/me` 验证身份，不信任浏览器传来的用户 ID。创建任务前使用同一 token 和 RLS 读取 `fin_account_data`；不使用 service-role 密钥。凭证不写入队列或日志。

同时兼容旧服务器会话。任务状态仅返回当前身份的任务。创建任务要求同源和 CSRF 自定义头。未登录或自选尚未同步时明确拒绝，不能用本地任意股票列表绕过权限。

本地演示可设 `MARKET_UPDATE_LOCAL_PREVIEW=1`，且请求 URL 与 Host 必须均为 loopback；线上绝不可开启该选项。此模式使用独立演示身份，不修改用户自选云数据。

## 部署条件（WorkBuddy 必须显式处理）

1. 网页服务配置 `MARKET_DATABASE_URL`（或 `DATABASE_URL`）、`MARKET_UPDATE_WORKER_ENABLED=1`、至少 32 字符的随机 `MARKET_UPDATE_WORKER_TOKEN`。线上创建队列必须有 PostgreSQL，不能把临时目录当队列。
2. **另行启动一个受进程管理器监管的执行器**：设置同一 `MARKET_UPDATE_WORKER_TOKEN` 与 `MARKET_UPDATE_ORIGIN=https://实际网站域名`，运行 `npm run market:worker`。执行器通过私有凭证调用 `/api/market-updates/worker`。浏览器永远不持有此凭证。
3. 网页部署环境必须允许该私有接口最长 300 秒请求（执行预算 210 秒）。如果平台有更短硬限制，必须改为常驻服务直接执行、或进一步拆分步骤；不能仅设置 `maxDuration` 就声称平台支持。可信定时调度也可调用私有接口，但需有足够执行时限和频率。
4. 执行器只有一个也能工作；多开实例仅提供接管，不提高并发。闲时每 15 秒检查队列；失败后等待 60 秒，成功处理一家公司后间隔 3 秒。重定向拒绝，防止凭证转发给其他地址。
5. 平台对服务器到自身 Cloud Auth/Database 网关的访问与 Origin 校验需要线上实测。本地通过 SDK 实际协议与模拟响应验证，不能冒称真实登录 token 已上线验收。

缺数据库、开关或执行器凭证时 API 明确返回服务未配置。执行器暂离线则任务保存，页面提示等待恢复，不把离线任务当已完成。只上传代码不会自动启动执行器或完成上述配置。

## 验证

针对性测试覆盖输入范围、跨用户共享、全局并发租约、重复提交、结果冻结、冷却跳过、断点接管、旧租约拒绝、限流退避、重试上限、身份与分组校验、CSRF、请求体上限、后台/前台隔离。

运行：`npm test`、`npm run build`。本地预览使用独立存储目录与执行器，实际点击按钮并关闭页面验证任务继续执行，再核实持久记录与重新打开的进度。

2026-10-21 本地验证结果：全站 342 项回归通过；随后近期范围限制、股息与共享列表输入等 51 项针对性检查通过，最终生产构建通过。以贵州茅台实际点击创建任务，重复提交返回同一任务；关闭页面后后台仍完成，价格、最新财务、分红、股本及列表财务输入均存在持久记录。重新进入后恢复进度，浏览器自动刷新可见页；列表 API 的财务序列与持久记录一致，浏览器无运行错误。另实测主镜像 501、备用镜像 200，拦截不会导致无节制重试。测试数据及任务文件位于 Git 忽略的本地 `data/`，不随代码提交。
