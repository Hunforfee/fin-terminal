# 采集与补齐修复说明

本次为本地代码修改。没有部署、写入线上数据库，未使用测试夹具代替原服务器数据。

## 执行计划

- daily 固定为单阶段 19：仅请求任务记录的 targetDate，不读取财报，不因 coverage 缺失启动初始化。
- 16:30 收盘与次日 06:30 恢复任务保留目标日。恢复不自动补前面的缺日。
- 来源仅返回其他日期、空数据或未收盘数据时，任务失败并说明可能休市/停牌；不虚构当日行情。
- 周日恢复安排 ten-year 历史计划，使用独立调度标识，避免被周六的恢复记录误跳过。
- financial 独立为阶段 20。披露月份 1/2/3/4/7/8/10 每日检查，其余月份每周检查。
  这是低频轮询，不是公告推送订阅；晚披露和修订依靠后续轮询及人工刷新发现。
- 历史、每日、财务任务使用不同执行标识；每日优先，其次财务，再处理历史。
  同一个目标日重复执行会复用已确认的数据。升级时旧 daily 历史阶段归零。
- 历史补齐仍会做完整性复核；旧年度三表已满足应有报告期和关键字段时跳过联网。
  近期年份、指标页、完整复权序列仍遵守各自刷新策略，不能声称所有来源都已支持按单个缺失字段查询。

## 行情与来源

每日向腾讯/东方财富发送 start=end=targetDate、count=1；不经过会扩展历史范围的页面 K 线读取器。
同源历史记录保留，新增目标日。未经核验的镜像不直接拼到 QMT 导入历史上。
如果数据库中已有至少三个价格一致的同日交集，允许用已保存的交集验证后扩展 canonical；
不会为验证交集额外请求历史。无交集时仅保存来源自己的记录，诊断中可看到不同序列截至日期。
周日/人工完整补齐负责处理这类来源对接，不能把“目标日已经存入某镜像”说成“所有页面均已更新”。

采集 HTTP 共享数据库来源锁与请求间隔，同一供应商子域归组。403/429/501/503 以及重复连接失败
保存冷却状态，Retry-After 参与计算，跨 worker/进程继续有效。进程死亡后锁会过期。
现有每任务预算与进程级冷却继续保留。该协调器由服务端采集上下文安装，不是对所有任意 fetch 的全站网络代理。

财务输入失败有持久化重试时间：旧年度 24 小时，其他输入 15 分钟。forceRefresh 可显式绕过该输入冷却，
但不绕过供应商限流。输入失败记录与来源冷却记录过期后由维护任务清理。

## 完整性与导入

financialPageQuality 按报告期检查：利润表归母净利润；资产负债表资产、负债、归母权益；现金流量表经营现金流。
零和负数均可为真实值。科目别名采用显式列表；遇到未识别的金融行业/旧报表名称会报告缺口，需要核实后扩展。
报告期齐全不代表已对照发行人原文核验。港股仍遵守独立的现有口径，新增细粒度诊断目前只覆盖 A 股三表。

finance 导入保留原有金额和日期，空输入不覆盖已知事实；写入后回读具体日期并返回 reconciliation：
requestedDates/savedDates/expectedDates/missingRequestedDates/missingInputs/status/digest。
status 区分 inserted、updated、unchanged；complete=false 时表示仍存在关键缺口，不抹掉已经成功保存的部分。
其他类型导入继续使用已有校验和返回结构，未冒充统一事务。

实际市场输入写入后清理对应证券的进程内缓存，并更新已有持久化估值输入版本。
跨进程估值根据版本失效；其他派生财务记录仍按各自数据库读取和刷新策略处理，不承诺所有派生记录立即重算。

## 诊断和巡检

原服务器新增只读查询：

`GET /api/market/data?resource=diagnostics&code=600415`

使用既有 x-fin-data-token / Bearer 鉴权。输出三表报告期和关键字段缺口、各来源行情范围、
股本窗口基准、估值版本匹配/缺输入及保存的 coverage。只读取数据库，不启动抓取、重算或排队。
缺失估值缓存与输入不完整分别表达，不用单一 ready 标志冒充所有指标可用。

worker 每分钟最多巡检一只已有行情股票，结果写入 market-audit:v1:<symbol>；同一证券 24 小时内跳过。
巡检不请求外部来源、不自动提交全市场补采。原有缺口台账仍由覆盖检查及采集失败更新。

手工批量只读巡检（在原服务器启用新接口后）：

```bash
node scripts/audit-market-data.mjs 600415
node scripts/audit-market-data.mjs --all
```

环境变量 MARKET_DATA_API_URL 指向原服务器 /api/market/data，MARKET_DATA_API_ACCESS_TOKEN
为读取凭证。--all 枚举已有行情标的，不能称为交易所全部上市公司。报告保存 data/audits，Git 忽略。
不在 URL、Git 或日志里放密钥。该脚本不写线上数据库。

## 线上验证所需

1. 原服务器 HTTPS 数据 API 地址及读取密钥（通过忽略的本地配置或环境变量提供）。
2. 原服务器部署本次代码后，再运行 diagnostics 及批量巡检，核对小商品城。
3. 要实际测试导入写入，还需现有 /api/market/import 的管理员授权方式；只读 token 不提供写权限。
4. 部署后确认 MARKET_UPDATE_WORKER_ENABLED 与 MARKET_CLOSE_UPDATE_ENABLED 已启用、独立执行器在线。
5. 数据服务器页面建议配置 MARKET_READ_MODE=database，避免浏览请求额外访问来源。
   远程预览继续按 docs/market-data-api.md 使用 MARKET_DATA_MODE=remote，不另起采集器。
