# 公网数据来源与备用策略

核查日期：2026-10-23。本轮仅处理通用来源；抓取、导入及展示的年份限制不变。

## 目前代码中的来源

| 数据 | 当前读取链路 | 适用范围与限制 |
| --- | --- | --- |
| 实时行情 | 腾讯 → 新浪 | A 股、港股。原服务器历史快照兜底是旧数据，不算新增公网来源；远程消费端仍只用原服务器 API。 |
| 历史日/周/月价格 | 腾讯 → 新浪（适用的不复权请求）→ 东方财富 | 按请求的复权类型、市场、日期范围严格校验。指数、股票和 A/H 证券身份不能混用；分钟线不等同于此日线链路。 |
| A 股利润表、资产负债表、现金流量表 | 新浪 → 东方财富 F10 结构化财报（本轮新增） | 所有按代码规范化的沪、深、北交所股票共用，无样本股票白名单。东财普通企业、银行、证券、保险分别有表族。不是承诺所有股票所有年份都有数据。 |
| A 股财务指标 | 新浪 → 东方财富主要指标（本轮新增） | 备用映射七项同口径指标：销售净利率、资产负债率、流动比率、速动比率、每股经营现金流、每股净资产、每股未分配利润。实际未披露项留空。加权 ROE、稀释 EPS、资产净利率不替代新浪不同定义的指标。 |
| 扣非利润、有息负债率、费用化利息 | 东方财富对应明确字段 | 不是以财务费用净额替代利息费用，不把缺失负债明细相加成零。 |
| A 股实际股本变动、已实施分红 | 新浪；分红另与东方财富方案核对 | 仍有单一基础来源依赖。股本金额不是实际股数，分红预案也不是已实施分红，不能用“另一个接口”冒充完整历史。 |
| 首次财报公告日期 | 新浪原始公告目录 + 东方财富披露记录 | 更正/修订时间不能当首次公告时间。备用财报返回的 NOTICE_DATE/UPDATE_DATE 仅保留为原始证据，不自动生成历史可知日期。 |
| 港股财务、实际派息 | 东方财富 HKF10 | 港股账本币种、主要指标标准化币种、港元每股派息分别处理；本轮 A 股三表备用不接入港股。 |
| 港股历史 PE/PB | 百度股市通公开历史样本 | 单独读取历史比率，不以当前财报倒填十年。当前估值与历史估值互不冒充。 |
| 公司资料、主营业务、公告、研报目录 | 主要是东方财富 F10/公告/研报公开接口 | 这几个域目前并非各有多家独立来源。 |
| 财报原文目录与链接 | 巨潮资讯公告查询 | 当前存结构化目录/原文链接，不把 PDF 二进制放入数据库，也没有把目录服务当完整三表解析器。 |
| iFinD | 可选配置的 HTTP/MCP 接入 | 需要服务和授权配置；不能计作已免费启用的独立公网财报来源。 |

## 本轮接入细节

- 东财端点：`https://datacenter.eastmoney.com/securities/api/data/v1/get`。
- 利润表 `RPT_F10_FINANCE_GINCOME`，主要指标 `RPT_F10_FINANCE_MAINFINADATA`。
- 资产负债/现金流表族分别为 `RPT_F10_FINANCE_{G|B|S|I}BALANCE` 和 `RPT_F10_FINANCE_{G|B|S|I}CASHFLOW`。普通企业明确返回“数据为空”时再试其他行业表；HTTP 限流、超时、格式错误不会触发无界探测。成功表族提示只在内存保留一小时，最多 512 项。
- 复用现有 `source-sina-page:*` / `source-sina-indicators:*` 标准化键，避免改库迁移、重复存储及另造一套显示读取器。键名是历史兼容名，实际来源写入记录 `source`、逐科目逐期 `fieldSources`，原始字段/币种/报告名/获取时间写入 `sourceEvidence`，共享数据 API 可直接读取。
- 财务金额从人民币元转为万元；每股收益维持元/股。缺失不是零，原有有效科目、报告期不会因备用回复较薄被删除。证券代码、交易所、人民币币种、季末日期、未来日期、重复报告期均校验。
- 库内有效输入继续优先；只有需要采集且新浪失败/空值时请求东财。数据库只读页面不发起额外抓取；采集器保存后，估值、财务体检、列表及 API 共用读取器。
- 403/429 暂停同一采集预算中的该域名，不再拦住独立域名。备用成功可继续任务；来源仍失败且遇到限流时，保留队列原有暂停机制。请求总预算、串行节奏和取消信号继续生效。
- MCP 缺口台账保留为最后补救；`attempts` 仍是缺口登记次数，不代表真实网络请求次数。

## 能继续增加哪些独立来源

1. **交易所/发行人原始披露**：上交所[经营业绩概览](https://www.sse.com.cn/disclosure/listedinfo/listedcompanies/)提供基于发行人 XBRL 的公开展示。适合作为沪市核对路径；不是已经接好的沪深北通用三表 API。需要独立验证分页、历史范围、原始/修订版本和字段语义后再接入。
2. **巨潮资讯结构化服务**：[深证信数据服务平台](https://webapi.cninfo.com.cn/)与现有公告目录是不同能力。需确认服务授权、接口权限和使用范围后接入，不能把未配置服务说成可用备用源。
3. **港交所/发行人报告**：[HKEX Annual Report Explorer](https://are.hkex.com.hk/disclosure-repository/en)可用于港股原始披露核对。结构化提取后仅存字段和证据链接；不把 PDF 放库。它不是当前所有港股三表自动回补已经完成的证明。
4. **新浪港股财务页**：公开页确实有三表/指标入口，但核验样本出现表间日期跨度、重复报告期与不同币种，尚不足以直接替换当前港股标准化财务。保持为候选，不把页面标题正确当作每格数据身份和单位已核验。

## 多来源的代价

备用链越长，全部失败时等待越久；接口变化维护成本增加；复权、币种、合并范围、累计/单季、归母/合计、原始/修订版本更容易冲突。多个域名或多个 MCP 工具也可能共同转接同一家上游，并不等于真正独立的多源。

策略是按数据域保留少量经过验证的独立来源，优先复用持久化有效输入，失败后有序切换并限额；无法核验的缺口继续明确显示，不能为减少 MCP 而编造值或混用口径。
