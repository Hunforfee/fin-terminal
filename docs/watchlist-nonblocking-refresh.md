# 自选列表非阻塞财务刷新

## 问题与方案

自选页原先直接 `response.json()`，空响应会显示原始解析错误；行情某批失败会退出全部行情加载。列表财务缺失或过期时同步等待多年的源页抓取，冷启动请求可能超过访问链路的等待上限。

本次把自选列表使用的财务请求形态（2 年、quarter、roe/netMargin/ocfPerShare/debtRatio 四项）改为读库显示、响应后补齐。其余自定义三表与十年对比请求、采集 worker 和全市场筛选协议保持原有行为；不能将本次结果视作所有财务端点均已异步化。

显示路径不请求行情，也不联网采集。优先读取 `watchlist-financial-inputs:v1:<symbol>`；没有派生记录时，只读复用已入库原始财报。无数据返回空序列与 pending 状态，不把等待当作失败或零值。过期派生数据保留来源及原始获取时间；冲突数据沿用原有待复核标记。真实缺失、刷新失败和无可写存储分别提供原因。

## 后台与负载

源站通过 Next.js `after()` 在返回响应后运行原有 `getWatchlistFinancialInputs` 采集、校验、合并、写库流程。每个 Web 进程最多同时执行 2 项任务，最多接受 8 项（含正在执行）；同证券去重，满额返回 busy，后续读取重试。执行预算 90 秒，沿用请求取消信号、跨进程抓取租约与来源限流。失败信息最多保留 256 项并冷却 60 秒；原有持久化来源失败冷却仍然有效。必须回读确认新记录可用，才能认为后台刷新成功。

这是响应后的有限刷新，不是新增持久化任务队列。Web 重启会丢失尚未完成的调度，已成功入库的数据保留；下次访问缺失记录会重新调度。长期无人访问的批量补齐仍由已有 worker 负责。数据库只读模式不启动刷新；远程消费者仍转发源服务器，不在消费者写库。

## 浏览器行为

自选页统一使用安全 JSON 读取工具，单次请求限时 20 秒（包含响应体读取）；取消页面加载保留取消语义。该超时仅在自选页显式启用，不改变 AI 等其他长请求。

行情某批失败保留缓存并继续后续批次。财务空序列不覆盖有效显示值。仅当前页每轮顺序重查四家公司一批，pending/busy 时隔 5 秒重查，最多 18 轮；翻页、切换账号、离开页面会取消旧轮询。达到上限显示暂停和手动重查入口，不无限轮询全部自选。失败原因可展开查看。

## 部署与验收

1. 在实际源服务器部署更新、重新构建并重启 Web；远程消费者也需要更新前端。保留数据库、连接配置和密钥。无需迁移或清库，也无需扩大连接池。
2. 确认源服务器 `MARKET_READ_MODE=hybrid`，持久化存储可写，Next.js 运行环境允许 `after()` 完成后台任务。
3. 分别检查已入库、过期、完全缺失、A 股和港股四种列表请求。缺失请求应先返回合法 JSON；后续重查能看到入库结果。验证来源失败时旧值、日期和具体失败原因保留。
4. 对空响应、非 JSON 响应、超时注入故障，确认不会出现原始 JSON 解析错误；某批行情失败后其他批次继续返回。
5. 本地隔离测试不能证明 WorkBuddy 的部署或公网链路已经恢复。十年财务对比冷启动、健康检查及后台 worker 自身卡顿需要单独在源服务器验证，本次没有操作其运行进程。
